# Wipeditt v1.2.6

Fix live comment discovery when classic Reddit's newest listing ends before older entries that are visible in the native top view. Version 1.2.5 read top only after the newest listing had reached the 1,000-entry boundary. That missed profiles where the newest view ended earlier while the all-time top view still exposed older comments.

The connector now reads the native top (`t=all`) ordering first, then the newest ordering. Both are always scanned. If either reaches classic Reddit's per-ordering boundary, the connector continues with controversial (`t=all`) and hot. A repeated forward cursor now moves to the next native ordering instead of ending the scan. The ordinary-overview supplement is no longer needed because top and newest are both covered.

Repeated rows are de-duplicated and each original is hydrated at most once per scan. Filters, item limits, account and author checks, review, confirmation, server pacing and write verification are unchanged. Post, comment and combined scans use the same ordering coverage.

Validation: unit coverage verifies that an older comment exposed by a short top listing is found even when the newest listing is shorter, that capped top and newest listings add the remaining orderings, that repeated cursors continue instead of stopping, and that post and combined scans start on their native tabs. The full source/build suite passes 118 tests; the isolated Electron Linux fixture suite passes top/new ordering continuation, native pagination, selection and the existing edit/delete safeguards. The new ordering path is synthetic; a signed-in live scan after release remains to be confirmed. No private endpoints, credentials or real account writes were used.

Listings remain partial. Classic Reddit may hide removed or inaccessible entries, and each native ordering has its own limit; importing `comments.csv` from the official export remains the complete-history path.

GPL-3.0-only. Official Linux x64 and Windows x64 packages, corresponding source ZIP and SHA256SUMS.
