# Wipeditt v1.2.5

Fix live comment discovery when classic Reddit's newest profile ordering ends before older entries. The maintainer's signed-in `comments/?sort=top` page exposed comments that a newest-only scan did not reach. Classic Reddit keeps separate newest, top, controversial and hot profile views and caps each cached ordering at 1,000 entries; following only the newest next links can therefore stop while another native ordering still exposes older history.

When the newest listing ends near that boundary, within 100 rows to allow for hidden or repeated entries, the connector now reads the native top (`t=all`), controversial (`t=all`) and hot orderings, follows their ordinary pagination and combines results with the existing de-duplication. Shorter profiles keep the existing overview supplement. Posts and the combined comment/post scan use the same ordering coverage. Repeated rows are hydrated at most once per scan; filters, item limits, account/author checks, review, confirmation, server pacing and write verification are unchanged.

Validation: unit coverage feeds a 950-entry newest listing and verifies that an older comment exposed only by top, plus entries from controversial and hot, are included once while a duplicate newest entry remains de-duplicated. The full source/build suite passes 115 tests, and the isolated Electron Linux fixture suite passes login, account verification, history continuation, selection, native writes and deletion safety without real Reddit writes. The new ordering path is synthetic; a signed-in live scan after release remains to be confirmed. No private endpoints, credentials or real account writes were used.

Listings remain partial. Classic Reddit may hide removed or inaccessible entries, and each native ordering has its own limit; importing `comments.csv` from the official export remains the complete-history path.

GPL-3.0-only. Official Linux x64 and Windows x64 packages, corresponding source ZIP and SHA256SUMS.
